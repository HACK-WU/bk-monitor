# TAPD 授权与建单 — 需求挖掘报告

> 本文档聚焦授权部分，建单流程不在本次范围内。

---

## 一、需求概述

### 1.1 需求形态

真实需求 — 跨系统集成的权限打通问题。

### 1.2 功能本质

在蓝鲸监控与 TAPD 两个独立系统之间建立**双层授权链路**，使监控平台能合法读取用户的 TAPD 项目、并以业务空间维度获得在 TAPD 项目中创建单据的能力。产品层面屏蔽 TAPD 双套 OAuth 的技术复杂度，让用户感知为「授权 → 选项目 → 建单」的线性流程。

### 1.3 背景

TAPD 存在两套独立的 OAuth 授权流程：

| 维度 | 用户态授权（User OAuth） | 项目应用态授权（App Install OAuth） |
|------|------------------------|----------------------------------|
| **目的** | 获取当前用户的 access_token，用于读取该用户有权限的项目列表 | 授权蓝鲸监控应用关联指定 TAPD 项目（项目级） |
| **授权 URL** | `https://tapd.woa.com/oauth/` | `https://tapd.woa.com/oauth/open_app_install` |
| **回调 resource** | `{"type":"user","user_id":"xxx"}` | `{"type":"workspace","workspace_id":"xxx"}` |
| **鉴权主体** | 用户维度（每个用户独立授权自己的 TAPD 账号） | 项目维度（项目管理员授权特定项目给应用） |
| **后续 API** | 用 Bearer Token 调业务 API | 用 Basic Auth (client_id:client_secret) 调项目级 API |
| **Token 有效期** | access_token 2h（一期不考虑 refresh_token） | 无独立 token，授权后通过 `get_granted_workspaces` 可查 |

## 二、使用场景

### 场景 1：冷启动（业务无已关联项目）

1. 用户打开弹窗 → 系统判断无已关联项目
2. 引导用户完成**用户态 OAuth**（跳转 `tapd.woa.com/oauth/`，用户同意 → 回调拿 code → 后端换 access_token）
3. 用 access_token 调 TAPD API 获取「当前用户有权限的项目列表」
4. 展示项目列表，已关联的项目标记为「已关联」并禁用操作
5. 未关联项目点击「去关联」→ 跳转**项目应用态授权 URL**（`tapd.woa.com/oauth/open_app_install`）
6. TAPD 授权通过后回调监控后端 → 写入关联关系 → 重定向回前端页面
7. 关联成功 → 项目出现在「已关联项目」下拉中

### 场景 2：日常使用（已有已关联项目）

直接展示已关联项目下拉 → 选项目 + 单据类型 → 建单

### 场景 3：追加关联项目

复用场景 1 的步骤 2-6

### 场景 4：非管理员协作

普通用户 → 复制应用态授权链接给管理员 → 管理员在浏览器完成项目应用态授权 → TAPD 回调监控后端自动完成关联 → 发起人刷新后看到项目已关联

---

## 三、用户角色

| 角色 | 参与的授权动作 |
|------|--------------|
| **普通用户（值班/处理人/研发）** | 完成用户态 OAuth（授权自己的 TAPD 账号），拉取项目列表，发起关联 |
| **TAPD 项目管理员** | 完成项目应用态授权（选项目 → 授权给蓝鲸监控应用） |
| **非项目管理员** | 复制授权链接转发给管理员，由管理员操作 |

---

## 四、核心痛点

1. **双套 OAuth 流程串联**：用户态 OAuth 和项目应用态 OAuth 是 TAPD 的两套独立流程，授权 URL、回调参数、鉴权方式均不同，产品层需要无缝串联。
2. **关联关系共享**：关联关系是 `space_id` ↔ `tapd_workspace_id` 多对多，一次关联全空间共享，需避免重复关联。
3. **回调重定向**：`open_app_install` 的 `cb` 回调是浏览器跳转场景，后端处理完关联写入后需 302 重定向回前端页面。
4. **授权状态多样**：前端需精确判断并展示对应页面（未用户态授权 / 已用户态无已关联项目 / 已有已关联项目），不能出现状态错乱。

## 五、技术需求清单（后端重点）

### 5.1 数据模型

| 编号 | 技术需求 | 说明 |
|------|---------|------|
| D-01 | **TAPD 项目关联表** | `space_id` ↔ `tapd_workspace_id` + `tapd_workspace_name`，唯一约束 `(space_id, tapd_workspace_id)` 保证幂等，一次关联全空间共享 |
| D-02 | **用户 TAPD Token 表** | 按用户维度存储 `access_token`、过期时间等。一期不存 `refresh_token` |

### 5.2 后端接口

| 编号 | 技术需求 | 说明 |
|------|---------|------|
| B-01 | **用户态 OAuth 回调接口** | 接收 TAPD 回调的 `code`，换取 `access_token` 并存储到用户 token 表，返回前端授权成功 |
| B-02 | **获取用户 TAPD 项目列表接口** | 用用户 `access_token` 调 TAPD API，返回当前用户有权限的项目列表，并与关联表比对标记已关联状态 |
| B-03 | **应用态授权回调接口（`cb`）** | `open_app_install?cb=xxx` 的回调地址，`cb` URL 中携带业务 ID。TAPD 授权通过后浏览器回调此接口 → 从业务 ID 获取 `space_id` + 从回调参数提取 `workspace_id`/`workspace_name` 写入关联表 → **302 重定向到前端页面**（具体地址暂定） |
| B-04 | **获取已关联项目列表接口** | 按 `space_id` 查询关联表，返回已关联 TAPD 项目供前端下拉 |
| B-05 | **生成用户态授权 URL** | 拼接 TAPD OAuth URL + `state` 参数，返回给前端做跳转 |
| B-06 | **生成应用态授权 URL** | 拼接 `open_app_install` URL，`cb` 参数指向 B-03 回调地址，返回给前端做跳转 |

### 5.3 关键流程逻辑

| 编号 | 技术需求 | 说明 |
|------|---------|------|
| S-01 | **关联幂等** | B-03 回调写入时通过唯一约束 `(space_id, tapd_workspace_id)` 防重，重复授权无副作用 |
| S-02 | **关联共享** | 同一 `space_id` 下所有用户共享已关联项目，无需每人重复关联 |
| S-03 | **项目列表标记已关联** | B-02 返回用户项目列表时，与关联表比对，已关联的项目标记状态，前端可直接禁用「去关联」按钮 |

### 5.4 前端概要（不展开）

| 编号 | 概要 |
|------|------|
| F-01 | 弹窗状态判断（有无已关联项目 → 不同页面） |
| F-02 | 用户态授权引导 → 跳转 → 回调回到弹窗 |
| F-03 | 项目列表展示 + 去关联/已关联状态 |
| F-04 | 非管理员复制链接给管理员 |
| F-05 | 已关联项目下拉 + 建单表单 |

## 六、关键约束与边界

| 约束 | 说明 |
|------|------|
| **一期不实现 refresh_token** | 用户态 token 过期后需重新引导用户授权，refresh_token 机制二期计划 |
| **不判断管理员/非管理员** | 无需通过 API 判断用户在 TAPD 项目中的角色，非管理员直接复制链接给管理员操作即可 |
| **关联关系维度** | `space_id`（蓝鲸业务空间）↔ `tapd_workspace_id`（TAPD 项目），多对多关系 |
| **回调方式** | `open_app_install` 的 `cb` 参数为浏览器回调，后端处理完后需 302 重定向到前端页面 |
